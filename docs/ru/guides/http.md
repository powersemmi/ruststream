# HTTP-фреймворки

RustStream - не HTTP-фреймворк. Сервис, который отдаёт HTTP-API и потребляет сообщения, запускает
обе стороны в одном процессе, на одном рантайме tokio. HTTP-фреймворк (axum, actix-web или любой
другой стек на tokio) работает рядом с приложением RustStream. Связывание ниже показано на axum.
Согласованными обе стороны держит транзакционный outbox.

Полный компилируемый пример лежит в
[`examples/http_outbox.rs`](https://github.com/powersemmi/ruststream/blob/main/examples/http_outbox.rs):

```text
cargo run --example http_outbox --features macros,memory,json
```

## Работа рядом с HTTP-сервером

Обе стороны запускаются в `main`. `start()` запускает сторону обмена сообщениями в фоне и
возвращает дескриптор `RunningApp`, который согласует два времени жизни:

=== "Макросы"

    ```rust
    --8<-- "examples/http_outbox.rs:wiring"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/http_outbox.rs:wiring"
    ```

`start()` подключает брокеры и открывает подписки. Он завершается, когда сервис уже работает,
поэтому ошибку запуска вы получите раньше, чем HTTP-сторона начнёт принимать трафик.

`stopping()` возвращает владеющий future. Он завершается, когда сторона обмена сообщениями
остановилась сама по отказу в режиме fail-fast. Его можно подставить в `with_graceful_shutdown` из
axum, чтобы HTTP-сервер остановился вслед за ней.

Явную штатную остановку запускает `shutdown()`. Вызывайте его после того, как HTTP-сервер
остановился. Последовательность остановки и [таймаут остановки](lifespan.md#shutdown-timeout)
описаны в руководстве по жизненному циклу.

Издателя HTTP-сторона получает через связывающий токен. `.bindable()` оборачивает брокер,
`bind(..)` выпускает токен до того, как приложение поглотит брокер, а `running.publisher(token)`
связывает токен с уже подключённым брокером. Связанный издатель - обычное значение, его можно
клонировать в любое состояние HTTP-фреймворка.

## Эндпоинт healthz {#a-healthz-endpoint}

`start()` отвечает только за готовность на старте. Состояние сервиса дальше показывает
health-проба. `RunningApp::health()` выдаёт клонируемый `HealthProbe`:

```rust
--8<-- "examples/http_outbox.rs:healthz"
```

`state()` возвращает снимок без блокировок: `Running`, `ShuttingDown`, `Stopped` или
`Failed { reason }` с диагностикой отказа в режиме fail-fast. После `shutdown()` проба продолжает
работать и возвращает конечное состояние. При отказе в режиме fail-fast `/healthz` отвечает 503,
даже если соседние задачи держат процесс запущенным.

У маршрута собственное состояние (`get(healthz).with_state(running.health())`), поэтому состояние
остального роутера может быть любым. В связывании выше `/healthz` зарегистрирован рядом с `/orders`.

Сторона подписчика - обычный обработчик. Тот же сервис потребляет события, которые создают его
HTTP-эндпоинты, и эти события видит любой другой сервис, подписанный на брокер:

=== "Макросы"

    ```rust
    --8<-- "examples/http_outbox.rs:handler"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/http_outbox.rs:handler"
    ```

## Публикация прямо из запроса

Самый простой вариант - положить издателя в состояние HTTP-фреймворка и публиковать прямо на пути
запроса: `publisher.message(&event).publish().await`, ровно как при
[публикации из обработчика](publishing.md). Так устроен полноценный сервер из
[руководства по метрикам](metrics.md).

Плата за это - связанность. Если брокер недоступен, HTTP-запрос возвращает ошибку или ждёт. Если
эндпоинт пишет ещё и в базу, между записью и публикацией появляется разрыв: при падении процесса
событие теряется, а при обратном порядке уходит по записи, которую откатили. Это ошибка
согласованности, и проявится она при ближайшем деплое. Разрыв убирает транзакционный outbox.

## Транзакционный outbox

Эндпоинт записывает событие рядом с бизнес-записью, а в брокер его переносит relay, поэтому запись
и событие появляются только вместе. Паттерн не привязан к HTTP, и у него есть
[отдельная страница](transactional-outbox.md). Она разбирает тот же пример
`examples/http_outbox.rs`.

## Попробуйте

```text
curl -X POST http://127.0.0.1:8080/orders \
  -H 'content-type: application/json' -d '{"id":1,"item":"book"}'
```

Ответ возвращается сразу, как только хранилище зафиксировало запись. Обработчик `fulfil` логирует
заказ чуть позже, когда relay опубликует событие.
