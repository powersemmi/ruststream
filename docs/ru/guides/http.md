# HTTP-фреймворки

RustStream - не HTTP-фреймворк. Когда сервис одновременно отдаёт синхронный HTTP-API и потребляет
сообщения, HTTP-фреймворк (axum, actix-web или любой другой стек на tokio) работает рядом с
приложением RustStream, в том же процессе и рантайме. Эта страница показывает связывание на примере
axum и паттерн, который делает такую связку надёжной, - транзакционный outbox.

Полный компилируемый пример лежит в
[`examples/http_outbox.rs`](https://github.com/powersemmi/ruststream/blob/main/examples/http_outbox.rs):

```text
cargo run --example http_outbox --features macros,memory,json
```

## Работа рядом с HTTP-сервером

Обе стороны поднимаются в `main`. `start()` поднимает сторону обмена сообщениями в фоне -
отрабатывает производитель состояния, подключается брокер, открывается подписка - и завершается,
когда сервис уже работает, так что сбой на старте всплывёт раньше, чем HTTP-сторона начнёт принимать
трафик. Возвращённый хендл `RunningApp` согласует два времени жизни. `stopping()` - это владеющий
future, который завершается, если сторона обмена сообщениями свернулась сама (отказ в режиме
fail-fast); он подставляется прямо в `with_graceful_shutdown` из axum, чтобы процесс не продолжал
обслуживать HTTP с мёртвым потребителем. `shutdown()` - это явная штатная остановка: хуки
`on_shutdown`, слив обработчиков в полёте, ограниченный
[таймаутом остановки](lifespan.md#shutdown-timeout), и остановка брокера - после того, как
HTTP-сервер уже остановлен. Публикатор приходит через связанный токен: `.bindable()` оборачивает
брокер, `bind(..)` выпускает токен до того, как приложение поглотит брокер, а
`running.publisher(token)` сводит токен с брокером, который `start()` уже подключил. Соседняя задача
получает живой публикатор, а состояние «не подключён» просто не возникает; живая форма - обычное
значение, которое безопасно клонировать в любое состояние HTTP-фреймворка:

```rust
--8<-- "examples/http_outbox.rs:wiring"
```

## Эндпоинт healthz {#a-healthz-endpoint}

`start()` - это ворота готовности; всё, что происходит после него, покрывает health-проба.
`RunningApp::health()` выдаёт дешёвый клонируемый `HealthProbe` поверх watch-канала: `state()` - это
снимок без блокировок (`Running`, `ShuttingDown`, `Stopped` или `Failed { reason }` с диагностикой
fail-fast), и проба переживает `shutdown()`, поэтому маршрут продолжает отвечать терминальным
состоянием. Это закрывает щель, которую один `stopping()` оставляет: если сторона обмена сообщениями
упала в fail-fast, а соседняя задача держит процесс живым, `/healthz` переключается на 503, вместо
того чтобы вечно отдавать 200 при мёртвом потребителе:

```rust
--8<-- "examples/http_outbox.rs:healthz"
```

Маршрут несёт собственное состояние (`get(healthz).with_state(running.health())`), поэтому уживается
с любым состоянием остального роутера - полное связывание выше регистрирует его рядом с `/orders`.

Сторона подписчика - обычный обработчик: тот же сервис потребляет то, что производят его
HTTP-эндпоинты, и эти события видит любой другой сервис, подписанный на брокер:

```rust
--8<-- "examples/http_outbox.rs:handler"
```

## Публикация прямо из запроса

Самая простая интеграция кладёт публикатор в состояние HTTP-фреймворка и публикует прямо на пути
запроса - ровно так же, как при [публикации изнутри обработчика](publishing.md):
`publisher.message(&event).publish().await`. Полноценный сервер из
[руководства по метрикам](metrics.md) так и делает, чтобы крутить свои счётчики.

Плата за это - связанность: теперь недоступность брокера роняет или подвешивает HTTP-запросы, а
падение после записи в базу, но до публикации теряет событие (или, при обратном порядке, публикует
событие для записи, которую откатили). Если эндпоинт ещё и пишет в базу, этот разрыв - баг
консистентности, который ждёт своего окна деплоя. Лечится он транзакционным outbox.

## Транзакционный outbox

Эндпоинт записывает событие рядом с бизнес-записью, а relay переносит его в брокер потом, так что ни
одна из сторон не может произойти без другой. Паттерн не привязан к HTTP, и у него есть отдельная
страница: [транзакционный outbox](transactional-outbox.md). Пример, который гоняет эта страница,
`examples/http_outbox.rs`, - тот же самый.

## Попробуйте

```text
curl -X POST http://127.0.0.1:8080/orders \
  -H 'content-type: application/json' -d '{"id":1,"item":"book"}'
```

Ответ возвращается сразу, как только хранилище зафиксировало запись; обработчик `fulfil` логирует
заказ чуть позже, когда relay опубликует событие.
