# Транзакционный outbox { #transactional-outbox }

Опубликовать событие и записать строку, которую оно описывает, - две операции. Падение процесса
между ними оставляет систему в несогласованном состоянии: заказ записан, а события нет, или событие
опубликовано, а заказ откатился. Outbox убирает эту несогласованность: событие становится частью
записи, а в брокер оно публикуется позже.

Паттерн не привязан к HTTP. Он нужен везде, где публикация должна быть согласована с записью в
базу. Пример ниже показывает его на axum-эндпоинте, самом частом случае. Полный компилируемый код -
[`examples/http_outbox.rs`](https://github.com/powersemmi/ruststream/blob/main/examples/http_outbox.rs):

```text
cargo run --example http_outbox --features macros,memory,json
```

## Запись события рядом с бизнес-записью { #recording-the-event-beside-the-write }

Вместо публикации на пути запроса эндпоинт записывает событие рядом с бизнес-записью. В брокер
записанные события переносит relay:

=== "Макросы"

    ```rust
    --8<-- "examples/http_outbox.rs:event"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/http_outbox.rs:event"
    ```

```rust
--8<-- "examples/http_outbox.rs:store"
```

Эндпоинт пишет только в хранилище. Заказ и его событие сохраняются одним атомарным шагом.
Ввода-вывода с брокером на пути запроса нет, поэтому недоступность брокера не задерживает ответ и
не превращает его в ошибку:

```rust
--8<-- "examples/http_outbox.rs:endpoint"
```

## Перенос outbox в брокер { #draining-the-outbox }

Фоновая задача переносит outbox в брокер. Строку она удаляет только после успешной публикации,
поэтому при недоступности брокера события задерживаются, но не теряются. Если процесс падает между
публикацией и удалением строки, после перезапуска строка публикуется повторно. Потребители
получают доставку at-least-once, обычный контракт outbox. Дубликаты они обрабатывают так же, как
повторные доставки от самого брокера:

```rust
--8<-- "examples/http_outbox.rs:relay"
```

С настоящей базой `Store` - это таблица бизнес-записей и таблица `outbox`, которые пишутся в одной
SQL-транзакции. Строки `outbox` relay читает в порядке вставки, публикует и удаляет. Остальное
не меняется: брокер, издатель и подписчик не знают об outbox.
