# Политика отказов

Обработчик может не вернуть исход по двум причинам: его тело **паникует** или входящая полезная
нагрузка не **декодируется**. Оба случая покрывает один набор значений политики. Значение вы можете
задать клаузой `on_failure(..)` отдельно для каждого подписчика.
Умолчания у паники и у декодирования разные, потому что эти отказы означают разное.

## Умолчания

Без клаузы подписчик работает со встроенными умолчаниями:

- **panic = `fail_fast`**: паника - это ошибка в коде. Рантайм логирует ошибку с именем подписки и
  начинает штатную остановку: отменяет токен остановки и выполняет хуки остановки.
  [`run`](../index.md) возвращает `Err` с ненулевым кодом выхода, по которому оркестратор
  перезапускает сервис.
- **decode = `drop`**: сбой декодирования обычно означает плохие внешние данные. Рантайм
  отбрасывает одно сообщение (nack без возврата в очередь) и не останавливает сервис: на
  недоверенной теме такая остановка была бы отказом в обслуживании. Тот же ключ завершает доставку,
  когда не разбирается [типизированный контракт заголовков](headers.md). Он же действует, когда тип
  нагрузки, который [десериализует себя сам](subscribers.md#raw-subscribers)
  (`#[derive(Deserialized)]`), отвергает байты в своём конструкторе.

=== "Макросы"

    ```rust
    --8<-- "examples/failure_policy.rs:defaults"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/failure_policy.rs:defaults"
    ```

## Как задать политику

Клауза `on_failure(panic = .., decode = ..)` задаёт значение для любого из двух ключей. Ключ,
который вы не указали, сохраняет умолчание:

=== "Макросы"

    ```rust
    --8<-- "examples/failure_policy.rs:tuned"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/failure_policy.rs:tuned"
    ```

Значения политики такие:

| Значение              | Что делает                                                            |
|-----------------------|-----------------------------------------------------------------------|
| `fail_fast`           | Логирует ошибку, начинает штатную остановку, и `run` возвращает `Err`. |
| `drop`                | Отбрасывает сообщение (`nack` без возврата в очередь).                 |
| `retry`               | Возвращает сообщение в очередь (`nack` с возвратом).                   |
| `retry_after(<dur>)`  | Возвращает сообщение в очередь после задержки (см. раздел про отложенную повторную доставку в [Подписчиках](subscribers.md)). |
| `skip`                | Подтверждает сбойное сообщение, чтобы перейти к следующему. Это не успех: сообщение потеряно необработанным. |

`retry` для сбоев декодирования выбирайте с осторожностью: полезная нагрузка, которая никогда не
декодируется, доставляется повторно бесконечно, если у брокера нет политики dead-letter или
ограничения на число доставок. `skip` - это осознанный аварийный выход при poison-message.

=== "Макросы"

    ```rust
    --8<-- "examples/failure_policy.rs:skip"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/failure_policy.rs:skip"
    ```

## Как это ведёт себя

- Панику перехватывает `catch_unwind`, поэтому паникующий обработчик не останавливает цикл
  диспетчеризации. При `fail_fast` доставка остаётся незавершённой, и брокер с повторной доставкой
  отдаст сообщение снова после перезапуска. При остальных значениях доставка завершается, и
  подписчик продолжает потреблять. Перехват работает только при раскрутке стека: в сборке с
  `panic = "abort"` процесса уже нет.
- Декодирование возвращает `Result`, а не паникует, поэтому раскрутки стека здесь нет. Ключ
  `decode` завершает доставку сообщения напрямую (см. [Кодеки](codecs.md#decode-failures)).
- На пакетном пути каждый элемент декодируется независимо, и ключ `decode` действует на каждый из
  них. Ключ `panic` действует на панику в пакетном обработчике. Перехвата паники по отдельному
  элементу нет.

Полный пример: [`examples/failure_policy.rs`](https://github.com/powersemmi/ruststream/blob/main/examples/failure_policy.rs).
