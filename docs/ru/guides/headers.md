# Типизированные заголовки

Заголовки сообщения едут как нетипизированная карта `name -> bytes`, это `HeaderMap`. Когда
приложение несёт в них настоящий контракт (идентификаторы, порядковые номера, итоговые счётчики),
объявить этот контракт может одна структура - и она сразу питает три поверхности: извлечение в
рантайме на стороне потребления, билдер публикации на стороне отправки и схему заголовков в
сгенерированном AsyncAPI-документе.

## Контракт

Контракт заголовков - это плоская структура: каждое поле называет заголовок, а значения - скаляры
(числа, булевы значения, строки, сырые байты, перечисления без данных) или их `Option`. По проводу
каждое значение передаётся строкой: фреймворк разбирает `"3"` в поле `u32` и так же записывает его
обратно, а схемы по-прежнему описывают логические типы.

```rust
--8<-- "examples/typed_headers.rs:contracts"
```

Имена полей - это имена на проводе; для имён, которые не годятся как идентификаторы Rust, используйте
`#[serde(rename = "x-task-id")]`. Поле `Option` равно `None`, когда заголовка нет; отсутствие
заголовка, объявленного не через `Option`, - нарушение контракта.

## Приём: экстрактор `Headers`

`Headers<T>` - это параметр-экстрактор: рантайм разбирает заголовки доставки в `T` до того, как
выполнится тело, поэтому обработчик начинает с проверенных типизированных значений. Нарушение
(отсутствующий заголовок, неразбираемое значение) до тела не доходит: доставка завершается по
политике `on_failure(decode = ..)` подписчика - той же, что покрывает не декодируемую полезную
нагрузку (по умолчанию drop), - после `WARN`, называющего подписку и тип контракта.

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:handler"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:handler"
    ```

`Headers` сочетается с телом, которое десериализует себя само (`&Frame<'_>` рядом с его
типизированными заголовками), и с любым другим экстрактором.

В пакетном обработчике заголовки остаются своими у каждой доставки, поэтому страница спаривает
каждый элемент с его контрактом: вход - `&[Message<H, T>]`, и `element.headers` лежит рядом с
`element.body`. Соответствие гарантировано конструкцией: элемент, у которого не удалось получить
полезную нагрузку или заголовки, завершается по той же политике `on_failure(decode = ..)` и до
обработчика не доходит - ровно как на пути одиночного сообщения. Параметр `Headers<..>` здесь
отвергается, а ошибка называет парный вход.

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:batch"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:batch"
    ```

Монтирование читается так же, как у любой другой формы, и на обеих поверхностях: `b.include(bulk)` в
области брокера, `Router::include` на пути роутера. Тип контракта едет в оси входа, поэтому обычный
пакетный маршрут декодирует его рядом с каждой полезной нагрузкой.

Когда по одному каналу идут сообщения, у которых заголовки различаются в зависимости от вида события,
стандартный экстрактор туда лучше не пускать: напишите свой на трейте [`FromContext`] - прочитайте
заголовок-дискриминатор из нетипизированной карты ([`HeaderMap::get_str`]), а затем соберите тот
контракт, которого требует этот вид. Объединение форм объявите на входном типе (см. следующий
раздел), чтобы документ по-прежнему показывал контракт целиком.

[`FromContext`]: https://docs.rs/ruststream/latest/ruststream/runtime/trait.FromContext.html
[`HeaderMap::get_str`]: https://docs.rs/ruststream/latest/ruststream/struct.HeaderMap.html#method.get_str

## Объявление контракта на типе сообщения

`#[derive(Outgoing)]` принимает `headers = Meta` рядом с адресатом: контракт становится частью типа.
Билдер публикации после этого требует ровно эти заголовки, а AsyncAPI-документ рисует схему рядом с
полезной нагрузкой везде, где встречается тип. Про половину с адресатом см.
[публикацию](publishing.md#declaring-where-a-message-goes).

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:messages"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:messages"
    ```

## Публикация: контракт в точке вызова

Маркер слота `Out` перечисляет типы сообщений, которые слот вправе публиковать:

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:dictionary"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:dictionary"
    ```

Необязательная третья позиция параметра `Out` объявляет набор сообщений, которые публикует этот
обработчик:

- `Out<impl Publisher, Events>` (или явный `()`) - без ограничений: любое объявленное сообщение;
- `Out<impl Publisher, Events, (ChunkDone, Progress)>` - список прямо на месте;
- `Out<impl Publisher, Events, ChunkDone>` - один объявленный тип (тип с `#[derive(Outgoing)]`
  объявляет сам себя);
- `Out<impl Publisher, Events, ConvertSends>` - перечисление с `#[derive(OutMessages)]`, каждый
  вариант которого оборачивает одну модель: переиспользуемый именованный набор (само перечисление -
  декларация на уровне типов, его никогда не конструируют).

Дальше тело публикует через билдер (обработчик выше), а компилятор следит за всей декларацией
целиком:

- `message(..)` с типом вне объявленного набора не компилируется: обработчик публикует то, что
  объявил, и ничего кроме;
- тип, объявивший `headers = Meta`, публикуется только через `.message(&value).with_headers(&meta)`:
  забыть заголовки или передать не тот их тип - ошибка компиляции;
- адресат берётся из собственной декларации типа, поэтому фиксированное имя в точке вызова не требует
  ничего, а шаблонное требует свои подстановки;
- позиция совместимости, как всегда, статически сверяется с политикой в точке монтирования:
  `Out<impl TransactionalPublisher, Events, (ChunkDone, Progress)>` требует политику, у которой живой
  издатель транзакционный, и объявленные публикации выполняются внутри её транзакций.

Полезная нагрузка, которую сервис уже держит закодированной, или чужой тип, на который декларацию не
повесить (голый `Vec<Frame>`), уходит через байтовую точку входа:
`out.raw(&bytes).to(dest).publish()`. У неё те же позиции для заголовков и никакого кодека; если
нагрузка заслуживает собственной декларации, заверните её в newtype с `#[derive(Outgoing)]`.
Newtype, который выводит и `Outgoing`, и
[`Serialized`](subscribers.md#raw-subscribers), - полноправный член словаря: адресата и заголовки
он объявляет как любая модель и публикуется через ту же типизированную точку входа,
`out.message(&export)`, - способ отправки выбирает тип, поэтому байты уходят байт в байт, а
позиции заголовков работают без изменений.

Контракт заполняет эту позицию один раз. То, что добавляет сам издатель, подкладывается снизу:
издатель, несущий один аргумент для каждого отправляемого сообщения, отдаёт его как основу, а поля
контракта сериализуются поверх этой основы поле за полем; см.
[откуда берутся заголовки](publishing.md#where-the-headers-come-from).

## Форма ответа

Обработчику с `publish("dest")` дополнительная декларация не нужна: документ питается собственным
контрактом типа ответа, а адресат уже указан в атрибуте.

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:reply"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:reply"
    ```

В рантайме заголовки ответа остаются там же, где были: их выставляет `PublishTransform` на издателе
ответа, а [`HeaderMap::insert_typed`] сериализует значение контракта в карту изнутри трансформа.

[`HeaderMap::insert_typed`]: https://docs.rs/ruststream/latest/ruststream/struct.HeaderMap.html#method.insert_typed

## Что показывает документ

С фичей `asyncapi` `build_spec` рисует:

- схему заголовков каждого принимаемого сообщения - из параметра `Headers<T>` обработчика или из
  контракта `#[message(headers(..))]` входного типа, когда обработчик извлекает заголовки вручную;
- по операции `send` на каждое объявленное исходящее сообщение - ответ каждой формы `publish(..)` и
  каждый тип сообщения, объявленный слотом, - и у каждой из них свои схемы полезной нагрузки и
  заголовков.

Схемы описывают логические типы полей (`task_id: integer`), тогда как на проводе значения - это
строковые заголовки.

## Тестирование

Внутрипроцессная обвязка прогоняет весь путь целиком: `with_headers(&meta)` на билдере вброса
отправляет доставку с типизированным контрактом, а журнал публикаций показывает заголовки, которые
породила типизированная публикация.

```rust
--8<-- "examples/typed_headers.rs:drive"
```
