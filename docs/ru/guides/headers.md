# Типизированные заголовки

Заголовки сообщения - это нетипизированный ассоциативный массив `имя -> байты`. Типизированные
заголовки - это структура, которая объявляет, какие заголовки есть у сообщения и какого они типа.
Объявить её вы можете на подписчике и на издателе.

## Контракт

Контракт заголовков - это плоская структура со скалярными полями: числа, булевы значения, строки,
сырые байты, перечисления без данных.

```rust
--8<-- "examples/typed_headers.rs:contracts"
```

Если имя заголовка не годится в идентификаторы Rust, вы можете задать его через
`#[serde(rename = "x-task-id")]`. Поле `Option` объявляет необязательный заголовок.

В заголовке значение хранится строкой: фреймворк разбирает `"3"` в поле `u32` и так же записывает
его обратно.

## Приём: экстрактор `Headers`

`Headers<T>` - экстрактор: рантайм разбирает заголовки доставки в контракт `T` до того, как
выполнится тело.

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:handler"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:handler"
    ```

Если обязательного заголовка нет или значение не разбирается, доставка до тела не доходит. Её
завершает политика `on_failure(decode = ..)` подписчика - та же, что покрывает недекодируемую
полезную нагрузку, по умолчанию `drop`. Перед этим фреймворк пишет `WARN` с именем подписки и типом
контракта.

`Headers` сочетается с любым другим экстрактором и с телом, которое десериализует себя само.

В пакете заголовки остаются своими у каждой доставки, поэтому вход пакетного обработчика -
`&[Message<H, T>]`.

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:batch"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:batch"
    ```

Элемент, у которого не разобрались полезная нагрузка или заголовки, до обработчика не доходит: его
завершает та же политика. Параметр `Headers<..>` здесь не компилируется, а ошибка называет парный
вход.

Монтируется такой обработчик как любой другой: `b.include(bulk)` в области брокера,
`Router::include` на пути роутера.

Когда в одну подписку приходят сообщения с разными наборами заголовков, вместо `Headers` вы можете
написать свой экстрактор на трейте [`FromContext`]: он читает заголовок-дискриминатор из
ассоциативного массива ([`HeaderMap::get_str`]) и собирает контракт, которого требует этот вид
события. Объединение всех форм объявите на входном типе (см. следующий раздел).

[`FromContext`]: https://docs.rs/ruststream/latest/ruststream/runtime/trait.FromContext.html
[`HeaderMap::get_str`]: https://docs.rs/ruststream/latest/ruststream/struct.HeaderMap.html#method.get_str

## Объявление контракта на типе сообщения

`#[derive(Outgoing)]` принимает `headers = Meta` рядом с адресатом: контракт становится частью типа.
Как объявляется адресат, описано в [публикации](publishing.md#declaring-where-a-message-goes).

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:messages"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:messages"
    ```

## Публикация: контракт в месте вызова

Маркер слота `Out` перечисляет типы сообщений, которые слот вправе публиковать:

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:dictionary"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:dictionary"
    ```

Необязательная третья позиция параметра `Out` объявляет набор сообщений, которые публикует этот
обработчик:

- `Out<impl Publisher, Events>` (или явный `()`) - без ограничений: любое объявленное сообщение;
- `Out<impl Publisher, Events, (ChunkDone, Progress)>` - список прямо на месте;
- `Out<impl Publisher, Events, ChunkDone>` - один объявленный тип (тип с `#[derive(Outgoing)]`
  объявляет сам себя);
- `Out<impl Publisher, Events, ConvertSends>` - перечисление с `#[derive(OutMessages)]`, каждый
  вариант которого оборачивает одну модель: именованный набор для нескольких обработчиков. Само
  перечисление - декларация на уровне типов, его никогда не конструируют.

Дальше тело публикует через билдер публикации (обработчик выше), а компилятор проверяет всю
декларацию:

- `message(..)` с типом вне объявленного набора не компилируется;
- тип с `headers = Meta` публикуется только через `.message(&value).with_headers(&meta)`;
- адресат берётся из декларации типа: фиксированное имя в месте вызова ничего не требует, шаблонное
  требует подстановок;
- позиция совместимости сверяется при компиляции с политикой, указанной при регистрации
  обработчика: `Out<impl TransactionalPublisher, Events, (ChunkDone, Progress)>` требует политику с
  транзакционным издателем, а объявленные публикации выполняются внутри транзакции этого издателя,
  под той же декларацией.

Готовые байты или чужой тип, которому декларацию не задать (`Vec<Frame>`), вы можете обернуть в
newtype, который выводит `Outgoing` и [`Serialized`](subscribers.md#raw-subscribers). Заголовки он
объявляет как любая модель, а публикуется через тот же `out.message(&export)` байт в байт.

Издатель может задать свою основу заголовков, поверх которой записываются поля контракта; см.
[откуда берутся заголовки](publishing.md#where-the-headers-come-from).

## Форма ответа

Отвечающему обработчику дополнительная декларация не нужна. Один derive на типе ответа объявляет
и контракт заголовков, и адресата, а документ сообщает и то, и другое.

=== "Макросы"

    ```rust
    --8<-- "examples/typed_headers.rs:reply"
    ```

=== "Вручную"

    ```rust
    --8<-- "examples/manual/typed_headers.rs:reply"
    ```

Заголовки ответа выставляет `PublishTransform` на издателе ответа: внутри трансформа значение
контракта записывает [`HeaderMap::insert_typed`].

[`HeaderMap::insert_typed`]: https://docs.rs/ruststream/latest/ruststream/struct.HeaderMap.html#method.insert_typed

## Что показывает документ

С фичей `asyncapi` `build_spec` добавляет в документ схему заголовков каждого сообщения:

- у принимаемого - из параметра `Headers<T>` обработчика или из контракта
  `#[message(headers(..))]` входного типа, когда обработчик извлекает заголовки вручную;
- у отправляемого - из контракта, объявленного на самом типе.

Схемы описывают логические типы полей: `task_id: integer`. Остальное содержимое документа
разбирает [руководство по AsyncAPI](asyncapi.md).

## Тестирование

Внутрипроцессная обвязка прогоняет весь путь: `with_headers(&meta)` на билдере вброса отправляет
доставку с типизированным контрактом, а журнал публикаций показывает заголовки, которые записала
типизированная публикация.

```rust
--8<-- "examples/typed_headers.rs:drive"
```
