# Кодеки и сериализация

Кодек превращает байты из сети в вашу типизированную полезную нагрузку и обратно. Это отдельный шов,
не связанный с брокером: на стороне потребления конвейер выглядит как
`байты -> Codec -> типизированная полезная нагрузка -> обработчик`, а на стороне публикации тот же
путь проходится в обратном порядке. Кодек фиксируется в точке монтирования обработчика, поэтому на
пути доставки он ничего не стоит.

## Встроенные кодеки

| Кодек | Фича | Подключает | Формат передачи |
|---|---|---|---|
| `JsonCodec` | `json` *(по умолчанию)* | serde_json | JSON |
| `MsgpackCodec` | `msgpack` | rmp-serde | MessagePack |
| `CborCodec` | `cbor` | ciborium | CBOR |

Фичи кодеков строго аддитивны: включайте столько, сколько нужно. От типов сообщений требуется только
вывести `serde::Deserialize` (и `Serialize`, если тип уходит в ответах).

## Кодек по умолчанию {#the-default-codec}

`DefaultCodec` - это псевдоним, выбираемый по фичам: `json`, если он включён, иначе `cbor`, иначе
`msgpack`. Именно его берут `include(def)` и `TypedPublisher::new(publisher)`, когда кодек нигде не
назван; ни тот, ни другой не принимают аргумент-кодек. Он существует, только когда включена хотя бы
одна фича кодека; без единой фичи кодека доступны только методы с явно заданным кодеком.

## Откуда берётся кодек декодирования {#where-the-decode-codec-comes-from}

Кодек декодирования фиксируется во время компиляции. `include` не принимает кодек аргументом: он
разрешает его по самому конкретному уровню, на котором вы кодек задали, от самого узкого к самому
широкому.

### На один обработчик {#per-handler}

Переопределить одно монтирование:

=== "Router"

    <!-- inline-rust: standalone Router-builder fragment; the compiled form is the with_broker tab below (codecs.rs:per_handler), which mounts the same chain via include_router -->
    ```rust
    router.with_codec(CborCodec).include(handle);
    ```


### На область

Задать один кодек для всех обработчиков в области `with_broker`:

```rust

```

### По умолчанию

Когда ни один из уровней выше кодек не назвал, `include` берёт
[`DefaultCodec`](#the-default-codec).

## Сторона публикации {#the-publish-side}

Публикаторы подчиняются тем же правилам: `TypedPublisher::new(policy)` кодирует ответы кодеком по
умолчанию, а `TypedPublisher::with_codec(policy, codec)` называет кодек явно. Декодирование входящего
запроса следует области (кодек области, заданный через `with_broker_codec`, или `Router::with_codec`
цепочки роутера, иначе кодек по умолчанию), а кодек ответа едет на стеке, прикреплённом через
`.publisher(..)`, - так что форматы запроса и ответа спокойно расходятся.

Кодека на тип сообщения не существует (нет ассоциированного кодека в трейте сообщения): кодек - это
свойство монтирования, а не типа.

## Ошибки декодирования {#decode-failures}

Когда декодирование не удалось, судьбу сообщения решает политика отказа; по умолчанию сообщение
отбрасывается (nack без возврата в очередь). Политика задаётся для каждого подписчика клаузой
`on_failure(decode = ..)`:

```rust
use ruststream::subscriber;

--8<-- "examples/codecs.rs:decode_failure"
```

Если вы собираете обработчики вручную, обёртка `Typed`, которую возвращает `typed(codec, handler)`,
принимает ту же политику через `on_decode_failure`.

Значения политики (`Drop`, `Retry`, `RetryAfter(..)`, `Skip`, `FailFast`), умолчания и оговорки про
повторы описаны в разделе [Политика отказов](failure-policy.md). Примеры с кодеками выше взяты из
[`examples/codecs.rs`](https://github.com/powersemmi/ruststream/blob/main/examples/codecs.rs).

## Свои кодеки

Кодек - это любой тип, реализующий трейт `Codec`, поэтому можно подставить свой и передать его
всюду, куда идёт встроенный кодек. Обобщите его по другому кодеку - и он станет составным:
внутренний кодек задаёт формат полезной нагрузки, а обёртка только преобразует байты вокруг него.
Кодек ниже обрамляет вывод внутреннего двухбайтовым заголовком с версией - ту же форму принимают и
конверт для schema registry, и шифрующая обёртка.

```rust
--8<-- "examples/custom_codec.rs:codec"
```

Обе стороны обёртки сообщают об ошибках через `CodecError`. Сбой внутреннего кодека - это уже
`CodecError`, и он уходит наверх через `?` без изменений. Сбой самой обёртки становится
`CodecError::Decode` (или `CodecError::Encode`) и несёт ваш собственный тип ошибки как источник,
поэтому сообщение называет слой, отвергнувший полезную нагрузку, и причину:
`decode failed: not an envelope: leading byte 0x7b`.

Свой кодек монтируется на тех же трёх уровнях, что и встроенный, - здесь все три сразу, чтобы
область, цепочка и ответ читались каждый своей строкой:

```rust
--8<-- "examples/custom_codec.rs:mount"
```

## Синхронная граница {#the-synchronous-boundary}

`Codec::encode` и `Codec::decode` синхронны, и это задаёт границу того, что может жить в кодеке:
только то, что уже решают константа и байты под рукой, - как тег версии выше. Интеграция, которой
для сериализации нужен ввод-вывод (разрешить идентификатор схемы в реестре, взять ключ из KMS),
сюда не помещается, а блокирующий вызов внутри кодека останавливает задачу доставки.

Такие интеграции живут на асинхронных краях: перекодируйте входящие полезные нагрузки на пути
доставки подписки, до того как их увидит кодек, а исходящие обрамляйте через
[`PublishLayer`](middleware.md#publish-side-middleware). Оба края асинхронны и умеют вернуть
ошибку. Ту же границу со стороны брокера описывает раздел
[Авторам брокеров](../broker-authors/index.md#middleware-on-the-async-edges).

Этот кодек - [`examples/custom_codec.rs`](https://github.com/powersemmi/ruststream/blob/main/examples/custom_codec.rs).
