# Контракт шаблонов

Крейт поставляет шаблон для [`cargo generate`](https://github.com/cargo-generate/cargo-generate).
Шаблон проверяется в CI того же крейта, поэтому заготовка не расходится с его API.

## Форма

Шаблон - это каталог, по которому `cargo generate` создаёт заготовку:

```
templates/<name>/
├── cargo-generate.toml   # манифест: описание, объявленные плейсхолдеры
├── Cargo.toml.liquid     # name = "{{project-name}}"; пины ruststream + крейта брокера
└── src/
    ├── main.rs           # билдер #[ruststream::app]
    ├── orders.rs         # обработчики #[subscriber]
    └── routes.rs         # Router, собирающий обработчики
```

- Плейсхолдеры записываются на Liquid-синтаксисе cargo-generate. Встроенный плейсхолдер
  `{{project-name}}` принимает значение `--name`, поэтому минимальный шаблон своих не объявляет.
- Манифест пакета называется `Cargo.toml.liquid`, и cargo-generate убирает суффикс при генерации.
  Без суффикса манифест сломал бы зависимость по git: cargo разбирает каждый `Cargo.toml`
  репозитория, не глядя на `exclude`, и отвергает манифест с плейсхолдером в имени пакета. Так же
  называйте любой другой шаблонный файл, который стал бы разбирать cargo.
- Манифест пакета закрепляет `ruststream` на поддерживаемой минорной версии, а крейт брокера - на
  его собственной.
- Каждому транспорту или топологии брокера - свой шаблон: например, `nats` и `nats-js` или
  `redis-stream`, `redis-pubsub`, `redis-list`.

Исходники шаблона с плейсхолдерами `{{...}}` до генерации не разбираются ни как Rust, ни как TOML.
Держите их вне рабочего пространства cargo: `exclude = ["templates"]`.

## Сборка в CI (сам контракт)

CI крейта создаёт заготовку из каждого шаблона и компилирует её с закреплёнными версиями. Если
изменение API ломает заготовку, это ловит CI, а не первая сборка у пользователя.

Задача проверки делает три шага:

1. устанавливает `cargo-generate`;
2. создаёт заготовку во временном каталоге:
   `cargo generate --path templates/<name> --name smoke`;
3. запускает в заготовке `cargo check`.

Между вторым и третьим шагом задача правит `Cargo.toml` заготовки. Она ставит в требование версии
ядра ту версию, которую собирает: `[patch.crates-io]` меняет только источник крейта, а
неопубликованный предрелиз не попадает в диапазон без предрелиза. Затем она добавляет
`[patch.crates-io]` с путём к локальной копии ядра, как это уже делает CI брокеров с соседними
репозиториями.

## Только аддитивные блоки

Блоки под фичи только добавляют код. `{% else %}` и отрицательные ветки `{% if not flag %}` в
шаблоне запрещены. Тогда заготовка без флагов - строгое подмножество заготовки со всеми фичами, и
одного `cargo check` со всеми фичами на шаблон хватает, чтобы найти любое расхождение с API.

С выключенными флагами остаются только ошибки в самом шаблоне, например висящий `use` или
незаполненный слот. Их проверяйте локально.

## Кому что принадлежит

- Ядро (`ruststream`) владеет только шаблоном `templates/memory` на своём in-memory брокере,
  поэтому `cargo generate` по умолчанию работает офлайн и без зависимости от крейта брокера.
- Крейт брокера владеет шаблонами своих транспортов и проверяет их в своём CI.
