# Контракт шаблонов

Крейт поставляет шаблон для [`cargo generate`](https://github.com/cargo-generate/cargo-generate).
Шаблон проверяется в CI того же крейта, поэтому заготовка не расходится с его API.

## Форма

Шаблон - это каталог, по которому `cargo generate` создаёт заготовку. Держите его вне рабочего
пространства cargo (`exclude = ["templates"]`): до генерации файлы с плейсхолдерами `{{...}}` не
разбираются ни как Rust, ни как TOML.

```
templates/<name>/
├── cargo-generate.toml   # манифест: описание, объявленные плейсхолдеры
├── Cargo.toml.liquid     # name = "{{project-name}}"; пины ruststream + крейта брокера
└── src/
    ├── main.rs           # билдер #[ruststream::app]
    ├── orders.rs         # обработчики #[subscriber]
    └── routes.rs         # Router, собирающий обработчики
```

Плейсхолдеры записываются на Liquid-синтаксисе cargo-generate. Минимальному шаблону хватает
встроенного `{{project-name}}`, который принимает значение `--name`.

Манифест пакета называется `Cargo.toml.liquid`, и cargo-generate убирает суффикс при генерации.
Без суффикса сломалась бы любая зависимость от крейта по git: cargo разбирает каждый
`Cargo.toml` репозитория, не глядя на `exclude`, и отвергает плейсхолдер в имени пакета. Так же
называйте любой шаблонный файл, который стал бы разбирать cargo.

Манифест закрепляет `ruststream` на поддерживаемой минорной версии, а крейт брокера - на его
собственной.

Каждому транспорту или топологии брокера - свой шаблон: например, `nats` и `nats-js` или
`redis-stream`, `redis-pubsub`, `redis-list`.

## Сборка в CI (сам контракт)

CI крейта создаёт заготовку из каждого шаблона и компилирует её с закреплёнными версиями.
Изменение API, которое ломает заготовку, находит CI, а не пользователь.

Задача проверки делает четыре шага:

1. устанавливает `cargo-generate`;
2. создаёт заготовку во временном каталоге:
   `cargo generate --path templates/<name> --name smoke`;
3. правит `Cargo.toml` заготовки: требует ту версию ядра, которую собирает, и добавляет
   `[patch.crates-io]` с путём к локальной копии ядра;
4. запускает в заготовке `cargo check`.

Версию приходится задавать явно: `[patch.crates-io]` меняет только источник крейта, а
неопубликованный предрелиз не попадает в диапазон без предрелиза. Такой же патч CI брокеров уже
ставит для соседних репозиториев.

## Только аддитивные блоки

Блоки под фичи только добавляют код. `{% else %}` и отрицательные ветки `{% if not flag %}` в
шаблоне запрещены. Тогда заготовка без флагов - строгое подмножество заготовки со всеми фичами, и
одного `cargo check` со всеми фичами на шаблон хватает, чтобы найти любое расхождение с API.

С выключенными флагами остаются только ошибки в самом шаблоне, например висящий `use` или
незаполненный слот. Их проверяйте локально.

## Кому что принадлежит

- Ядро (`ruststream`) владеет одним шаблоном, `templates/memory`, на своём in-memory брокере.
  Заготовка из него не зависит ни от крейта брокера, ни от сервера, поэтому `cargo generate` по
  умолчанию работает офлайн.
- Крейт брокера владеет шаблонами своих транспортов и проверяет их в своём CI.
