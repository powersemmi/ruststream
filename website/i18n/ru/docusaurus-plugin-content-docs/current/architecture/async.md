# Асинхронность

Какие задачи держит работающий сервис, как через них проходит одна доставка и в каком порядке их
останавливает завершение работы.

<Diagram name="asyncTopology" words={topology} />

Сервис работает на Tokio. [`#[ruststream::app]`](../components/application/app-macro.md) строит
многопоточный рантайм. `flavor = "current_thread"` выбирает однопоточный, а `worker_threads = n`
задаёт число потоков.

Подписчик - это `Stream` доставок, и обратное давление возникает из самого опроса. Цикл по
умолчанию запрашивает следующую доставку, только когда предыдущая подтверждена.
[`workers(n)`](../components/subscribers/dispatch/workers.md) держит в работе не больше `n`
доставок. `workers(n, by_key)` отдаёт все доставки одного ключа одному воркеру, поэтому порядок
внутри ключа сохраняется. [`threads(n)`](../components/subscribers/dispatch/threads.md) читает
вперёд не больше `n × 9` доставок: по одной в руках каждого потока и по восемь в его кольце.

Выделенный поток проводит доставку целиком, от декодирования до подтверждения, на собственном
однопоточном рантайме. Работа, которую обработчик передаёт в
[`MainRuntime`](api:ruststream::runtime::MainRuntime) через
[`Ctx<MainRuntime>`](../components/subscribers/context/ctx.md), выполняется в рантайме приложения.

## Одна доставка {/* #one-delivery */}

<Diagram name="asyncTimeline" words={timeline} />

По умолчанию задача обработки - это сама задача цикла, при `workers(n)` - задача-воркер, при
`threads(n)` - выделенный поток. Продолжение
[`and_after`](../components/subscribers/messages/and-after.md), хук после подтверждения и таймер
[`retry_after`](../components/subscribers/messages/retry-after.md) запускаются после
подтверждения как задачи, которые приложение отслеживает. Они выполняются не больше одного раза:
доставка к этому моменту уже подтверждена.

## Завершение работы {/* #shutdown */}

<Diagram name="asyncShutdown" words={shutdown} />

[Тайм-аут завершения](../components/application/running/shutdown.md) ограничивает ожидание. Когда
он истекает, ещё работающие циклы прерываются, а незавершённые отслеживаемые задачи оставляются
доделывать своё самостоятельно. Без тайм-аута завершение ждёт их все. Задача, запущенная обычным
`tokio::spawn` на выделенном потоке, не отслеживается и заканчивается вместе с потоком.
