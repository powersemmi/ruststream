# Local memory

`LocalMemoryBroker` - полноценный брокер, который работает внутри одной прошивки. Он входит в фичу
`memory` крейта `ruststream` и подключается вместе с `embassy` (или с `compio` без `tokio`). Это
шина рантайма embassy, как [брокер Memory](memory.md) - шина рантайма tokio. Его типы не
`Send`, он работает на любом исполнителе и не читает часы. С него начинается шаблон
`embassy-memory` для `cargo generate`.

```toml
ruststream = { version = "0.8", default-features = false, features = ["embassy", "memory", "macros", "postcard"] }
```

## Что он поддерживает

| Область | `LocalMemoryBroker` |
|---|---|
| Подписки | тема по имени (`#[subscriber("sensors/temp")]` или `LocalMemorySource`) |
| Доставка | подписка получает то, что опубликовано после её открытия |
| Подтверждение | `ack` и `nack` с повторной постановкой в очередь и без неё; каждая доставка сообщает свой счётчик доставок; `retry_after` и мёртвые письма работают через копии, которые публикует рантайм; они хранятся в ёмкости `.retry_capacity::<CAP>()` точки монтирования |
| Пакеты | обработчики `&[T]`, до размера пакета точки монтирования; пакет не бывает больше, чем вмещает подписка |
| Публикация | обычные публикации и ответы через `LocalMemoryPublish` |
| Ёмкость | каждая подписка хранит `N` сообщений (константный параметр брокера), включая те, что сейчас у обработчика; публикация в переполненную подписку возвращает `LocalMemoryError::Full` |
| Тестирование | шина сама служит внутрипроцессным режимом: встроенный `TestApp` запускает приложение сервиса на ней на хосте |

У шины своя форма для каждой сборки фреймворка:

| | С `alloc` | Без `alloc` |
|---|---|---|
| Где хранится шина | в куче | в `LocalMemoryBus`, который плата объявляет как `static` |
| Конструктор | `LocalMemoryBroker::<N>::new()` | `LocalMemoryBroker::<N>::new(&BUS)` |
| Полезная нагрузка | любого размера | не больше `PAYLOAD` байт; 64, если шина не задаёт другое |
| Одновременно открытых подписок | любое число | не больше `SUBSCRIPTIONS`; 8, если шина не задаёт другое |
| Пакет | `Vec` доставок | фиксированный слот не больше чем из `N` доставок |
| Аллокации | шина и её каналы | нет: сборке не нужен аллокатор |

Фиксированная шина работает внутри критической секции, поэтому реализацию `critical-section`
предоставляет бинарный крейт. Шина, в которой нет места ни для одного сообщения, байта или
подписки, не собирается.

Как с ней работать, описано в компоненте [Local memory broker](../components/memory/local.md), на
странице [Embedded runtime](../components/application/embedded-runtime.md) и на странице
[встроенного `TestApp`](../components/application/testing/embedded-app.md).
