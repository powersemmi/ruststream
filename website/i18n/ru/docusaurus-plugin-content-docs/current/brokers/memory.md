# Memory

`MemoryBroker` - полноценный брокер, который работает внутри процесса сервиса. Он входит в фичу
`memory` крейта `ruststream` и не требует сервера, поэтому подходит для очереди, которая нужна
одному приложению. С него начинается шаблон `cargo generate` по умолчанию. Он работает на рантайме
tokio; рантайм embassy и compio без tokio работают на [брокере Local memory](local-memory.md).

```toml
ruststream = { version = "0.8", features = ["macros", "memory", "json"] }
```

## Что он поддерживает

| Область | `MemoryBroker` |
|---|---|
| Подписки | тема по имени (`#[subscriber("orders")]` или `MemorySource`) и шаблон по именам тем (`MemoryPattern`) |
| Доставка | подписка получает то, что опубликовано после её открытия; хранимый журнал ещё и воспроизводит сообщения с заданной позиции |
| Подтверждение | `ack`, `nack` с повторной постановкой в очередь и без неё, а также отложенный `nack`, который шина удерживает сама, поэтому `retry_after` не публикует копию; каждая доставка сообщает свой счётчик доставок |
| Пакеты | обработчики `&[T]`, пакет набирается жадно до размера пакета точки монтирования |
| Публикация | ключи раздела для каждого сообщения, транзакции (`TransactionalPublisher`, `OwnedTransactions`) и запрос-ответ (`RequestReply`) |
| Повторное чтение | хранимый журнал (`Seekable`, `Positioned`) |
| Ёмкость | не ограничена: шина хранится в куче |
| Тестирование | шина сама служит внутрипроцессным режимом: `TestApp` запускает на ней приложение сервиса без изменений |

Как с ним работать, описано в компонентах [Memory broker](../components/memory/index.md): сам
брокер и его прелюдия, [хранимый журнал](../components/memory/retention.md) для повторного чтения и
[подписки по шаблону](../components/memory/patterns.md).
