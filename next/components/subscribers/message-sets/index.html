    Message sets

    An enum deriving InMessages declares several message types on one subscription: a rule picks the variant, and the document lists one message per variant.

    The set is an enum whose variants each wrap one model, and the handler takes a reference to the enum: &OrderEvent, or &[OrderEvent] for a batch. Each model derives MessageInfo, because the document lists it by that name. A model decodes through its own path: the codec of the mount for a serde type, its own reader for a type that derives Deserialized, such as a Protobuf message. One set may hold both, so a JSON event and a Protobuf event share a subscription and each shows its own format in the document. The derive is the receiving counterpart of OutMessages, which declares what a slot sends.

    The header rule is the one to reach for when the producer can set a header. #[in_messages(header = "event")] on the enum names the header the set reads, and #[in_messages(value = "..")] on each variant names the value that picks it. The chosen variant decodes once; a set costs what a single type costs, plus the header lookup. A delivery without the header, or with a value no variant declares, is a decode failure naming the header and the value seen, settled by the failure policy like any other. The document carries the rule: each message's headers schema lists the header with its const value.

    A rule of your own is a function: #[in_messages(discriminate = path)] names one that reads the delivery, its headers and raw payload, and returns which kind to decode. The derive generates the kind enum, OrderUpdateKind for a set OrderUpdate, with one unit variant per model. The function returning None is a decode failure naming the set. This is the form for a rule no attribute states: a schema id, a field of the payload, a shape of the bytes. A broker crate may ship such a function for its own format.

    A rule only the decode codec can answer is a type: #[in_messages(discriminate_with_codec = ByRecord)] names one that implements CodecDiscriminator. A schema registry is the case: each record carries a schema id, and only the registry codec knows which record the id stands for. The type's kind(codec, msg) reads the codec of the scope or router and the delivery, and returns the kind the way a function does; None is the same decode failure. An impl that bounds the codec makes the set mount only under codecs that satisfy the bound: a set mounted under a codec that cannot answer is a compile error at the mount site. The call is static, so a delivery pays only for what the type itself does. Such a set decodes per codec, so it does not implement InMessages itself: it is a handler input everywhere a set is, and a bound of your own written as T: InMessages does not accept it. A broker crate may ship the type for its own registry.

    A set with no rule tries its variants left to right, and the first that decodes wins. The order of the variants is the rule, so put the strictest model first. Every variant failing is one decode failure that carries each variant's error. Each attempt costs one decode of that variant, so a delivery of the last variant pays for every variant before it. Left to right is exact only as far as the formats are strict: a Protobuf reader skips the fields it does not know, so a payload of one Protobuf model may decode as another, and a JSON object with the right fields decodes as any model that has them. For such sets, name a rule, or order the variants from the strictest to the loosest.

    The derive checks the declaration: every variant wraps exactly one model, each model implements MessageInfo, a model appears once in a set, the enum takes no generic parameters, and a variant owns its model, so a type that borrows the payload cannot be one. A set is not a message, so MessageInfo is not derived on the set itself. Each of these is a compile error on the variant or the enum it concerns. A serde enum with #[serde(tag = "..")] or #[serde(untagged)] is still an ordinary input type, but it is not a set: it works for serde formats only, the tagged form buffers the whole payload per delivery, the untagged form needs a self-describing format, and the document shows one message for the enum.

    The header rule, on a set of a JSON model and a Protobuf one:

    examples/in_messages.rs
    /// Every event of an order on the `orders` subscription: the `event` header names the model.
    #[derive(InMessages)]
    #[in_messages(header = "event")]
    enum OrderEvent {
        #[in_messages(value = "created")]
        Created(OrderCreated),
        #[in_messages(value = "cancelled")]
        Cancelled(OrderCancelled),
    }
    examples/manual/in_messages.rs
    /// Every event of an order on the `orders` subscription: the `event` header names the model.
    enum OrderEvent {
        Created(OrderCreated),
        Cancelled(OrderCancelled),
    }

    /// The kinds of the set, what a discriminator names; the derive generates this enum.
    #[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
    enum OrderEventKind {
        Created,
        Cancelled,
    }

    impl InMessages for OrderEvent {
        type Kind = OrderEventKind;

        fn decode<DecodeCodec, M>(codec: &DecodeCodec, msg: &M) -> Result<Self, CodecError>
        where
            DecodeCodec: Codec,
            M: IncomingMessage,
        {
            let kind = match msg.headers().get("event") {
                Some(b"created") => OrderEventKind::Created,
                Some(b"cancelled") => OrderEventKind::Cancelled,
                Some(other) => {
                    return Err(CodecError::Decode(
                        format!(
                            "the `event` header is `{}`, which names no variant of `OrderEvent`",
                            String::from_utf8_lossy(other)
                        )
                        .into(),
                    ));
                }
                None => {
                    return Err(CodecError::Decode(
                        "the delivery carries no `event` header".into(),
                    ));
                }
            };
            // The chosen variant decodes once, through its model's own path.
            let payload = msg.payload();
            match kind {
                OrderEventKind::Created => {
                    <OrderCreated as InVariant<Self>>::decode_variant(codec, payload)
                        .map(OrderEvent::Created)
                }
                OrderEventKind::Cancelled => {
                    <OrderCancelled as InVariant<Self>>::decode_variant(codec, payload)
                        .map(OrderEvent::Cancelled)
                }
            }
        }

        // One entry per model, in the order of the variants, each with the header value that names
        // it; the document lists them as the messages of the subscription.
        fn incoming() -> Vec<IncomingMessageMetadata> {
            vec![
                <OrderCreated as InVariant<Self>>::describe()
                    .with_discriminator(HeaderDiscriminator::new("event", "created")),
                <OrderCancelled as InVariant<Self>>::describe()
                    .with_discriminator(HeaderDiscriminator::new("event", "cancelled")),
            ]
        }
    }

    impl Input for OrderEvent {
        type Axis = SoloSet<Self>;
    }

    /// The definition value `#[subscriber("orders")]` would have minted: the body reads the set,
    /// decoded as the variant the header named before the call.
    struct OnEvent;

    impl Handle<OrderEvent> for OnEvent {
        fn handle(
            &self,
            event: &OrderEvent,
            _outs: &(),
            _ctx: &mut Context<'_>,
        ) -> impl Future<Output = Result<(), HandlerOutcome>> {
            match event {
                OrderEvent::Created(created) => tracing::info!(created.id, "created"),
                OrderEvent::Cancelled(cancelled) => tracing::info!(cancelled.id, "cancelled"),
            }
            ready(Ok(()))
        }
    }

    A rule of your own, over the generated kind enum:

    examples/in_messages.rs
    /// The same models under a rule no header states: the first byte of the payload tells JSON
    /// from Protobuf. The function reads the delivery and names the kind to decode.
    #[derive(InMessages)]
    #[in_messages(discriminate = by_payload_shape)]
    enum OrderUpdate {
        Created(OrderCreated),
        Cancelled(OrderCancelled),
    }

    fn by_payload_shape(message: &impl IncomingMessage) -> Option<OrderUpdateKind> {
        match message.payload().first()? {
            b'{' => Some(OrderUpdateKind::Created),
            _ => Some(OrderUpdateKind::Cancelled),
        }
    }

    #[subscriber("orders.updates")]
    async fn on_update(update: &OrderUpdate) -> HandlerOutcome {
        match update {
            OrderUpdate::Created(created) => tracing::info!(created.id, "created"),
            OrderUpdate::Cancelled(cancelled) => tracing::info!(cancelled.id, "cancelled"),
        }
        HandlerOutcome::ack()
    }

    A rule that asks the decode codec: the codec names records, and the set mounts under it through a router.

    examples/in_messages.rs
    /// What a registry codec answers beside decoding: the record a schema id stands for.
    trait RecordNames: Codec {
        fn record_name(&self, schema: &[u8]) -> Option<&'static str>;
    }

    /// JSON whose records a schema registry names; the registry here is a fixed table.
    #[derive(Debug, Clone, Copy)]
    struct Registry;

    impl Codec for Registry {
        fn encode<T: Serialize>(&self, value: &T) -> Result<BytesMut, CodecError> {
            JsonCodec.encode(value)
        }

        fn decode<T: DeserializeOwned>(&self, bytes: &[u8]) -> Result<T, CodecError> {
            JsonCodec.decode(bytes)
        }
    }

    impl RecordNames for Registry {
        fn record_name(&self, schema: &[u8]) -> Option<&'static str> {
            match schema {
                b"1" => Some("OrderCreated"),
                b"2" => Some("OrderPlaced"),
                _ => None,
            }
        }
    }

    /// An order was placed through the legacy checkout: the same JSON shape as `OrderCreated`, so
    /// only the registry tells the two apart.
    #[derive(Debug, Serialize, Deserialize, schemars::JsonSchema, MessageInfo)]
    struct OrderPlaced {
        id: u64,
    }

    /// Records named by the registry the scope codec holds: every delivery carries a schema id,
    /// and only the codec knows which record it stands for.
    #[derive(InMessages)]
    #[in_messages(discriminate_with_codec = ByRecord)]
    enum OrderRecord {
        Created(OrderCreated),
        Placed(OrderPlaced),
    }

    /// Asks the codec which record the `schema` header names. It accepts every codec that names
    /// records, so the set mounts only under such a codec.
    struct ByRecord;

    impl<DecodeCodec: RecordNames> CodecDiscriminator<OrderRecordKind, DecodeCodec> for ByRecord {
        fn kind<M: IncomingMessage>(codec: &DecodeCodec, msg: &M) -> Option<OrderRecordKind> {
            match codec.record_name(msg.headers().get("schema")?)? {
                "OrderCreated" => Some(OrderRecordKind::Created),
                "OrderPlaced" => Some(OrderRecordKind::Placed),
                _ => None,
            }
        }
    }

    #[subscriber("orders.records")]
    async fn on_record(record: &OrderRecord) -> HandlerOutcome {
        match record {
            OrderRecord::Created(created) => tracing::info!(created.id, "created"),
            OrderRecord::Placed(placed) => tracing::info!(placed.id, "placed"),
        }
        HandlerOutcome::ack()
    }

    Left to right, the strictest model first:

    examples/in_messages.rs
    /// No rule: the variants are tried in their order, and the first that decodes wins. The JSON
    /// model comes first because it is the stricter one: a Protobuf reader skips what it does not
    /// know, so Protobuf bytes never pass as JSON while the reverse could happen.
    #[derive(InMessages)]
    enum OrderChange {
        Created(OrderCreated),
        Cancelled(OrderCancelled),
    }

    #[subscriber("orders.changes")]
    async fn on_change(change: &OrderChange) -> HandlerOutcome {
        match change {
            OrderChange::Created(created) => tracing::info!(created.id, "created"),
            OrderChange::Cancelled(cancelled) => tracing::info!(cancelled.id, "cancelled"),
        }
        HandlerOutcome::ack()
    }
