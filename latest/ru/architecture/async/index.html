    Нормативная версия документации - английская

    Эта страница переведена с английского языковой моделью. При любом расхождении верен английский оригинал.

    Асинхронность

    Какие задачи держит работающий сервис, как через них проходит одна доставка и в каком порядке их останавливает завершение работы.

    Сервис работает на Tokio. #[ruststream::app] строит многопоточный рантайм. flavor = "current_thread" выбирает однопоточный, а worker_threads = n задаёт число потоков.

    Подписчик - это Stream доставок, и обратное давление возникает из самого опроса. Цикл по умолчанию запрашивает следующую доставку, только когда предыдущая подтверждена. workers(n) держит в работе не больше n доставок. workers(n, by_key) отдаёт все доставки одного ключа одному воркеру, поэтому порядок внутри ключа сохраняется. threads(n) читает вперёд не больше n × 9 доставок: по одной в руках каждого потока и по восемь в его кольце.

    Выделенный поток проводит доставку целиком, от декодирования до подтверждения, на собственном однопоточном рантайме. Работа, которую обработчик передаёт в MainRuntime через Ctx<MainRuntime>, выполняется в рантайме приложения.

    Одна доставка​

    По умолчанию задача обработки - это сама задача цикла, при workers(n) - задача-воркер, при threads(n) - выделенный поток. Продолжение and_after, хук после подтверждения и таймер retry_after запускаются после подтверждения как задачи, которые приложение отслеживает. Они выполняются не больше одного раза: доставка к этому моменту уже подтверждена.

    Завершение работы​

    Тайм-аут завершения ограничивает ожидание. Когда он истекает, ещё работающие циклы прерываются, а незавершённые отслеживаемые задачи оставляются доделывать своё самостоятельно. Без тайм-аута завершение ждёт их все. Задача, запущенная обычным tokio::spawn на выделенном потоке, не отслеживается и заканчивается вместе с потоком.
